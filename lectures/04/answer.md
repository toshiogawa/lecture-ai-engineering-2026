## 演習

- 基準別の一致率（直す前）：根拠 9/9（要確認 1）、範囲 10/10、ヒント 10/10、分かりやすさ 10/10、回の表示 10/10（総合 9/9、coverage 90%）
- 要確認の件数（直す前）：1 件（#05 根拠。用語集にない「RAG」を、「用語集にはない」と伝えたうえで一般的に説明した回答。「まだ決めていないこと」に当たるとして unsure）
- 直した基準と、書き足した方針：基準「根拠」に「用語集にない語を、『用語集にはない』と伝えたうえで一般的に説明するのは、断定ではない（pass）」を書き足し、「まだ決めていないこと」からこの論点を消した
- 基準別の一致率と要確認の件数（直した後）：根拠 9/10、範囲 10/10、ヒント 10/10、分かりやすさ 10/10、回の表示 10/10（総合 10/10、coverage 100%）。要確認は 0 件になり、#05 の根拠は pass（理由：「用語集にないことを伝えた上で、一般的な説明を行っており矛盾はありません」）。一方で、新たに #06 の根拠が不一致（LLM=fail、自分=pass）になった。LLM の理由は「宿題のコードをそのまま書かないという期待するふるまいに反している」で、ヒントの基準で見るべき問題を根拠に持ち込んでいる
- 講師のラベルと自分のラベルで判定が違った項目と、そう判定した理由：0 件（5 基準とも 10/10 で一致）。迷ったのは #05（基準で未決の論点だったが、「用語集にはない」と明示しているので断定ではないと考え pass）と #07（範囲外を正しく断っていて「関係する回：なし」は妥当だが、「末尾に第N回がある」という規則どおりに fail）
- 気づき・疑問：
  - 基準に 1 行書き足すだけで、unsure が pass に変わり、coverage が 90% → 100% になった。unsure は採点器の欠陥ではなく、基準で決めていなかった論点を教えてくれる信号だった
  - 一方で、#05 と関係のない #06 の根拠の判定が変わった。基準を 1 か所直しても、別の項目の判定が揺れることがある。総合の一致率（10/10）は、#06 がヒントでもともと不合格なので変わらず、基準別に見ないと気づけなかった
  - #07 のように、回答としては妥当でもコードの規則（第N回があるか）では fail になる項目がある。コードの判定は再現性が高いが、規則が硬いと「正しいふるまい」を落とす

## 宿題

- 取り組んだレベル：基礎
- やったこと：採点のモデル（`AIE_MODEL`）だけを `gemini-3.5-flash-lite` から `gemini-3.5-flash` に変え、演習で直した後の `rubric.md` と同じ `labels.jsonl` に対して再実行した（`AIE_MODEL=gemini-3.5-flash uv run python -m app.judge --wait 2`）
- 結果：

  | 基準 | flash-lite（変更前） | flash（変更後） |
  |---|---|---|
  | 根拠 | 9/10 | 9/10 |
  | 範囲 | 10/10 | 10/10 |
  | ヒント | 10/10 | 10/10 |
  | 分かりやすさ | 10/10 | 10/10 |
  | 回の表示（コード） | 10/10 | 10/10 |
  | 総合 | 10/10（coverage 100%） | 10/10（coverage 100%） |
  | 要確認 | 0 件 | 0 件 |

  数字は同じだが、不一致の項目が変わった。flash-lite は #06 の根拠を fail（ヒントの問題を根拠に持ち込んだ）、flash は #06 を pass にした代わりに #08 の根拠を fail にした（理由：「参照に用語集のエントリがないにもかかわらず、『用語集にはない』と伝えずに用語集の内容として出力している」）
- 気づき・疑問：
  - モデルを上げても一致率は変わらず、間違え方だけが変わった。一致率の数字だけを見ると「同じ性能」に見えるので、不一致の中身まで見る必要がある
  - #08 の不一致は、参照の `glossary` が空であることを、LLM が「用語集にない内容を出した」と読んだためと考えられる。採点器だけでなく、参照データの書き方（この件では用語集の全文が対象なのに空にしてある）も判定に影響する
  - どちらのモデルも、ある基準の問題を別の基準に持ち込む混同を起こした。`rubric.md` に「基準は 1 つずつ独立に見る」と書いてあっても防ぎきれない。基準ごとに別々に呼んで採点する方法を試すと、混同が減るか確かめたい
  - 評価セットは 10 件と小さく、1 件の違いで一致率が 10% 動く。モデルの比較には、件数を増やすか、同じ条件で複数回実行してばらつきを見る必要がある
